# Criteria fixed before trial results

## Feature-pilot gates

- Tangible progress: a reproducible win over the cached baseline or a substantive
  correctness/infrastructure improvement, with unsuccessful work shown.
- Hill climbing: at least two distinct, understandable contributor actions can
  change the score, without weakening the target set, basis, or checker.
- Transfer: the frozen candidate must be tested on the three predeclared new
  mass/kinematic settings; failures and overhead count. One-loop transfer is not
  a proxy for multi-loop performance.
- Home hardware: measured peak memory and wall time should leave room for an
  ordinary high-end home CPU session; no proprietary solver or GPU required.
- Intelligence: evaluate a reasoned change to computation structure, alongside
  knob search and an equally cached baseline. A single session cannot establish
  a causal comparison between agent intelligence and random/CPU search.
- Public demo: show the same complete mathematical task getting cheaper, with
  a verifiable identity and a clear link to particle-physics calculations.
- Scientific relevance: distinguish known implementation improvements from new
  IBP algorithms. Feature status should depend on a bridge to mature solvers
  and at least one multi-loop benchmark, not an impressive toy percentage.

A negative result on the held-out cases is useful evidence. It must not be hidden
by selecting only the development box or changing the test set after evaluation.
