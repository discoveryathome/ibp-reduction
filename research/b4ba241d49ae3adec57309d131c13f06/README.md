masters**, with exact agreement against the frozen sparse certificates. Both
native `masters` and `masters.final` agree with the preferred lists; all seven
native logs report zero unreduced requested integrals. The 35 inputs generated by
PR #7 were used byte-for-byte, without configuration changes.

This is **author-checked correctness replication**, not independent review or
acceptance. No production speed, master minimality, or new-family claim follows.

```sh

git -C ../ibp-predecessor checkout --detach d051133ed7c01652e21b53e34fcd5610051705a8
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python research/b4ba241d49ae3adec57309d131c13f06/verify_saved.py \
  --predecessor ../ibp-predecessor
```

No solver installation is needed for this saved-export replay. It checks:

- The pinned predecessor and all 12 source/certificate bindings in the original
  generated manifest, plus all 35 input digests.
- All 115 exact identities using the predecessor importer and unchanged core

  `d,s,t,m,u`, not numerical samples.

  and each saved execution receipt/export/log binding.
- Three analytic tadpole ratios from
  `I_a/I_1 = product((2j-d)/(2jm), j=1..a-1)`.
- Ten rejecting controls: empty/malformed/duplicate master metadata, incorrect
  sector metadata, empty/missing/duplicate target exports, a coefficient error

## Native build and execution

`BUILD.md` gives the source/build recipe. `BUILD.json` binds source commits and
trees, downloaded archives, build options, toolchain, Python dependencies,
executable and ten runtime libraries. Upstream Kira source remained pristine.
The actual solver was Kira 3.0 at
`fb745431f97c8899a512e638da8598b0cfad7521`, release build, without FireFly/FLINT,
on Linux x86_64, GCC 14.2.0, with CLN 1.3.7, GiNaC 1.8.10, yaml-cpp 0.7.0,
system GMP 6.3.0/zlib 1.3.1, and the separately downloaded official Linux Fermat.
Fermat's banner identifies version 7.9b; its archive/executable digests are pinned.
Third-party binaries, documentation, archives and intermediate databases are not
redistributed. The native coefficient exports and complete stdout/stderr logs are.
Raw `.log`/`.kira` whitespace is preserved for exact byte/digest replay; the local
`.gitattributes` excludes only those receipts from Git whitespace warnings.

`run_native.py` validates the generated inputs and predecessor source bindings,
then runs tadpole before the other families. It stops on the first failure and
records it. Each trial uses one Fermat worker, a 180-second timeout and a 2 GiB
address-space cap per process. `native/run-receipts.json` records the command,
exit status, elapsed/CPU time, peak individual-process RSS and evidence digests.
RSS is not aggregate simultaneous memory. The seven native calls took 33.190
seconds in total; those receipts exclude source builds, input generation,
Python exact comparisons and session work, and are **not benchmark timings**.
Build wall time was not separately instrumented.

The release and integer arithmetic diagnostics each had zero mismatches in
100,009 cases against an unsigned-128-bit remainder oracle, with a 64-bit
`long double` mantissa. `probe_arithmetic.py` reuses the project's prior probe
without overwriting its saved result. This finite diagnostic is not an exhaustive
arithmetic proof; the identities above are checked separately and exactly.

## Failures and corrections retained

No solver run failed and no generated Kira input required correction. Three setup
issues were resolved before the native reductions, with their scope recorded in
`BUILD.json`:

1. GNU tar's initial ownership restoration failed in the sandbox. Partial source
   trees were removed, re-extracted with `--no-same-owner`, and all extracted CLN
   and GiNaC files compared byte-for-byte with the pinned archives before builds.
2. The inherited probe's mixed `uint64_t`/`ULL` initializer lists failed under GCC.
   Explicit `uint64_t` constants fixed the diagnostic harness; Kira's arithmetic
   source was unchanged. `logs/arithmetic-probe-initial.log` retains the failure.
3. The first driver could not launch absent `/usr/bin/time`; no solver started.
   Standard-library `os.wait4` replaced that optional measurement dependency.
   `logs/native-tadpole-missing-time.log` retains the failure.

Source screens had zero high findings. yaml-cpp's three warnings concern unused
CI install scripts; tests/tools were disabled. The screen's generic executable
warning on separately downloaded Fermat was checked against its actual provenance:
it was outside git, not a project-committed executable. No global install or
upstream author contact occurred.
